# SPLAT design decisions

One line per decision, newest last. Format: `[Phase N] decision — reason`.

- [Phase 1] Target `net10.0` (SDK 10.0.404 installed); warnings are errors via `Directory.Build.props`.
- [Phase 1] `SourceSpan` lines/columns are 1-based; `Length` counts UTF-16 chars; end-of-file spans have length 0 and render with one caret.
- [Phase 1] A span running past its first line is underlined to the line end plus `...`; tabs in the source are copied into the caret padding so alignment holds at any tab width.
- [Phase 1] Spec section 9 messages are verbatim in `Templates`; the `Fix:` line is separate technical text. Quip rotation (new categories only) is seeded by line number so output is deterministic.
- [Phase 1] Color only when stderr is not redirected and `NO_COLOR` is unset.
- [Phase 2] `#- -#` block comments nest, so commented-out code may itself contain block comments. An unterminated one is reported at its opening `#-`.
- [Phase 2] Strings may span lines. Escapes: `\n \t \r \0 \" \ \{ \}`; an unknown escape is an error but is kept literally. A literal `{` must be written `\{`; a bare `}` is literal.
- [Phase 2] A string always lexes to one `String` token carrying `Parts` (`TextPart` / `ExprPart`). `ExprPart.Offset` is the file offset of the expression, so the parser re-lexes that range with `new Lexer(src, diag, offset, offset+len)` and gets correct spans. The format spec starts at the first top-level single `:` (not `::`/`:=`, not inside `()[]{}` or nested strings) and runs to the `}`.
- [Phase 2] `c"..."` is a `Char` token only when `c` is immediately followed by `"`; value is the Unicode scalar (int). Must contain exactly one scalar.
- [Phase 2] Integer literal value is `ulong` (range checking against i32/etc. and negation are the type checker's job); float value is `double`. Underscores are allowed anywhere inside digit runs. A number running straight into a letter/digit/underscore (`12abc`, `0b102`) is an error.
- [Phase 2] `:` inside `[...]` (innermost open bracket is `[`) is `SliceColon`; inside `(...)` within brackets it is a block `Colon` again. `::` and `:=` are always `DoubleColon` / `ColonAssign`.
- [Phase 2] `'` is `Transpose` only after Ident, `)`, `]`, `me`, or another transpose; `''` is one `ConjTranspose` token (so `A'''` = `''` then `'`). Elsewhere it is an error whose fix points at `c"a"`.
- [Phase 2] `||` is two adjacent `Pipe` tokens; the parser tells norm bars from lambda bars using `Token.SpaceBefore` (no space = adjacent). `|>` is `PipeGreater`, so write `||v|| > 3` with a space, not `||v||>3`.
- [Phase 2] `>>` is always `GreaterGreater`; the parser must split it when closing nested generics (`Maybe<Maybe<i32>>`).
- [Phase 2] Norm suffixes `_1`, `_inf`, `_F` lex as ordinary identifiers directly after the closing bars (`SpaceBefore == false`); the parser consumes them.
- [Phase 2] `grad/∂`, `intg/∫`, `sum/∑`, `prod/∏` share one `TokenKind` each. Because `sum`/`prod`/`grad`/`intg` are lexed as keywords, the parser (Phase 4/14) must accept them as plain function names when not followed by `[` (reduction/integral) or `(` (grad); until then they are reserved.
- [Phase 2] Extra assignment operators lexed beyond the spec list: `*=`, `/=`, `./=`. Bad characters and bad literals never stop lexing; `Lexer.Tokenize` never throws and always ends with `EndOfFile`.
- [Phase 2] `splat tokens file.splat` dumps tokens (stdout) and diagnostics (stderr, exit 65).
- [Spec v0.3] Added Milestone 5, the built-in data engine ("crates", spec §11, build plan Phases 19-28). It needs these later lexer changes (Phase 20): keyword `crunch`, duration literals (`5s`, `1mo`), date/stamp literals (`d"..."`, `t"..."`). The Phase 2 lexer is unchanged until then; today `5s` is reported as a bad number.
- [Phase 3] The parser is recursive descent for statements plus a Pratt loop for expressions. Binary table (spec 8.1): `**` (right-assoc, above unary) > unary `- ! & ~` > `@ .* ./ · \` > `* / % .+ .-` > `+ -` > `.. ..=` (non-associative; `1..2..3` is an error) > comparisons (left) > `and` > `or` > `|> >>` (left). `and` binds tighter than `or` (spec table lists them on one level; plan recommendation adopted). Assignment is a statement, not an expression.
- [Phase 3] Postfix `'`/`''`, calls, indexing (`A[:, 0..3]`, `:` alone is `FullSlice`), member access, `[a, b]` list literals and string-template interpolation already parse here. Lambdas, norms, calculus, reductions, `guess`/`judge` and data-engine forms are Phase 4+.
- [Phase 3] `:` opens a block and each `;` closes exactly one, so `;;` is simply two closers. An `hmm` chain (`hmm`/`meh`/`nah`) is one statement closed by one `;`; a nested `hmm` takes the following `meh`/`nah` (dangling-else), so it needs its own `;` first.
- [Phase 3] Whitespace stays insignificant, with three same-line rules: the value after `yeet`/`rip` must start on the same line as the keyword; a command call's first argument must be on the same line as the callee; nothing else is newline-sensitive. So `x :=` followed by a statement on the next line is read as a continuation.
- [Phase 3] Command-call rule: only the prelude names `squish`, `yell`, `slurp` may be called without parentheses, and only when the next token is on the same line, after a space, and is a literal, name, `me`/`elder`, `!`, `&` or `~`. Arguments are comma-separated to the end of the expression. `f (x)` and `f(x)` are both ordinary calls; `-`, `[` and `(` never start a command argument.
- [Phase 3] Error recovery: missing `;` is reported once per unclosed block at its opening `:` (innermost first) when the file ends; a broken statement skips to the next statement keyword, `;`, `meh`/`nah`, or an identifier starting a line; a missing `:` after an `hmm`/`meh`/`spin` header is reported and the body is parsed as if it were there; an orphan `meh`/`nah` swallows its own header, body and `;`. A `;` sitting exactly where an error was just reported is not reported again at top level.
- [Phase 3] Nesting deeper than 200 (blocks, expressions, types) reports `TooDeep` instead of overflowing the stack.
- [Phase 3] `mold quirk teach mood pick yolo zone nuke yoink brain grind` are skipped by the parser with a `HARD HAT AREA` error (block skipping counts `:` and `;`, treating the `:` after `meh`/`nah`/`oops` as a continuation) and appear in the AST as `ReservedStmt(keyword)`; the owning phase replaces that with real nodes. `guess`/`judge` are not statements, so they stay Phase 4.
- [Phase 3] `cook op <symbol>` parses `+ - * / % ** @ == != < <= > >=` and `[]` (Phase 8 rejects the unsupported ones); `cook op(...)` with a paren is a function named `op`. `birth` and `funeral` are accepted as cook names. Generic bounds (`T: Quirk`) and `$Dim` parameters parse; a closing `>>` or `>=` after generics is split by the parser.
- [Phase 3] `splat ast file` prints s-expressions, `splat ast --fmt file` prints canonical source. Tests assert `parse(format(parse(x)))` has the same s-expression and that the formatter is idempotent. `SPLAT_UPDATE_GOLDEN=1 dotnet test` rewrites the `.ast`/`.err` expectations in `tests/golden` for review.
- [Phase 4] Prefix `|` is a norm opener only when the next token is a `|` with no whitespace or newline before it (`||v||`); otherwise it opens a lambda. A zero-parameter lambda must be written `| | e`. Closing a norm uses the same adjacent-pair test, so `||a|| or ||b||` and `|x| ||x||` both parse. Lambda parameters are bare identifiers (no `::T` yet).
- [Phase 4] A lambda body is a full expression (extends as far right as possible, up to `,` `)` `]` `;`). `x |> |a| a + 1` therefore puts the whole `a + 1` in the lambda.
- [Phase 4] Norm suffixes accepted: `_1`, `_2` (same as no suffix), `_inf`, `_F`, and only when glued to the closing bars; any other `_name` glued there is an error. Postfix `'` after a norm is not valid (the lexer only emits Transpose after an identifier, `)`, `]` or `me`), and a norm is a scalar anyway.
- [Phase 4] `∑/sum[i in range] body` and `∏/prod[...]` take as body an expression parsed at the additive level, so the body absorbs `+ - * / % @ ...` but stops at `..`, comparisons, `and`/`or` and `|>`: `∑[i in 0..N] i + 1` is `∑(i + 1)`, while `∑[i in 0..N] i == 6` is `(∑ i) == 6`. Parenthesise to override. The formatter wraps a reduction in parentheses whenever it is an operand of arithmetic.
- [Phase 4] `∫/intg[r1, r2, ..., name = v] |x, y| body`: every non-named entry must be a `..`/`..=` range (anything else is a parse error), named entries are options (e.g. `tol`), and the integrand must be a lambda. `∂/grad` is a deriv node only when followed by `(`; `∫/intg`, `∑/sum`, `∏/prod` only when followed by `[`; otherwise all four are ordinary names (so `sum(v)`, `map(xs, sum)` work).
- [Phase 4] `guess(cfg) fit (X, y)` / `judge(cfg) fit (X, y)` parse to `FitExpr`. `cfg` is a normal argument list: bare names (`linear`), calls (`svm(kernel = "rbf")`) and `name = value` entries. The result is a primary expression, so `model(&X)` and `.r2(...)` chain off it. Mapping of keywords to algorithms is Phase 15's job.
- [Phase 4] `splat ast -e "<expr>"` prints one expression as a single-line s-expression (used for the precedence table). Float literals print as .NET round-trip text (`1E-06`).
- [Cross-phase] Diagnostic IDs: every diagnostic has a permanent ID, `SE` + 5 digits (error) or `SW` + 5 digits (warning), separate sequences, never renumbered or reused. Registry: `DiagnosticCodes.Table` in `Splat.Core` (one entry per `DiagnosticCategory`), exposed as `Diagnostic.Code`. `ConsolePrinter` prints `[SE00001] ` before the headline; `Message` text (spec 9 wording) is unchanged. Blocks: 00001 lex/parse, 00100 names/types/shapes, 00200 ownership/zones, 00300 runtime, 00400 OOP/patterns, 01000 data engine (reserved in spec 9), 90000 internal. `DiagnosticCodeTests` fails on an unregistered category, a duplicate code, or a severity/prefix mismatch. Introduced after Phase 4; existing categories were assigned codes then and golden `.err` files regenerated.
- [Phase 5] Pipeline: lex -> parse -> `TypeChecker` (one static pass over the whole program) -> `Interpreter`. Nothing runs if the checker reports an error, so type errors always precede side effects. The checker records literal types, cook signatures, pipe desugarings and named-argument maps in `TypeInfo`, which the interpreter reads (the interpreter never re-infers).
- [Phase 5] Types: `i8 i16 i32 i64 u8 u16 u32 u64 usz smol mid chonk bit txt char zip`, `range<T>` and `cook(A)::R`. The char type is named `char` (the spec lists no name). `smol` is IEEE half, `mid` f32, `chonk` f64, and every float result is rounded to its own precision. `usz` is 64-bit unsigned.
- [Phase 5] Literal defaulting: an integer literal is `i32`, a float literal is `mid`, but a literal takes the type its context asks for (annotation, parameter type, the other operand: `n + 1` with `n::i64` is an i64 add). An integer literal never becomes a float and vice versa (`x::mid = 42` is an error; write `42.0`). A literal that does not fit is a compile error (`-128` fits an i8).
- [Phase 5] No implicit conversions at all. Explicit conversion syntax is the type name as a function: `mid(x)`, `i64(n)`, `u32(c"A")`, `char(97)`, `txt(v)` (any value, including ranges). `T(x)` is checked at runtime for range (`BadConversion`); float to int truncates toward zero; NaN/inf are errors. `bit(x)` does not exist (compare instead). A user binding named like a type shadows the conversion.
- [Phase 5] Integer arithmetic is CHECKED, never wrapping: any result outside the type's range is `IntegerOverflow` (SE00304). Division/remainder truncate toward zero and divide-by-zero is an error; float division by zero is IEEE (inf/NaN). `**` on integers with a negative exponent is a runtime `MathDomain` error (SE00307). `+` also concatenates two `txt`. Comparisons need identical types; `txt` compares by ordinal UTF-16 code units.
- [Phase 5] Scoping: `:=` is immutable, `wag` mutable, only `wag` can be reassigned (`=`, `+= -= *= /=`; the reassigned value must keep the variable's type). Shadowing in a nested scope is allowed (and may change the type); redeclaring a name in the SAME scope is an error (`Redeclared`, SE00107), because closures capture by reference and a same-scope rebind would change their view. Phase 6's REPL will relax this for session-level names. A bind's initialiser sees the outer binding (`x := x + 1` in a nested block). Variables must be declared before use; functions are hoisted per block so mutual recursion works. A `spin i in` variable is immutable and fresh per iteration.
- [Phase 5] Functions: parameters must be annotated; the return type defaults to `zip` for block bodies and is inferred for `= expr` bodies (a self-recursive one needs `::T`, `CannotInfer` SE00112). The value of a block body is `yeet`'s value or its LAST expression (also through an `hmm ... nah` chain); a function with a non-`zip` return type must return on every path (`MissingReturn`, SE00110); a trailing `spin:` with no `bail` counts as returning. Defaults (`h::i32 = 2`) and named arguments work for `cook` declarations, not for function-typed values. Generic parameters (`<T>`) are accepted and treated as "any" until Phase 7.
- [Phase 5] Lambda parameters are inferred from context (an expected `cook(...)::R` type, or the left side of `|>`); with no context they must be annotated `|x::i64| ...` (parser change: `LambdaParam` gained an optional `Type`). Closures capture variables by reference (shared mutable cell), so a closure counter works.
- [Phase 5] `x |> f` is `f(x)` and `x |> f(a, b)` is `f(x, a, b)` (left side becomes the first argument); the checker stores the desugared call and the interpreter runs it.
- [Phase 5] Format specs in `{x:spec}`: `[<>^]? 0? width? .precision? [xXbo]?`. Precision is for floats only, radix letters for integers only, validated at check time (`BadFormat`, SE00111). Numbers default to right alignment, text to left; negative numbers in a radix print as `-` plus magnitude. A float prints in shortest round-trip form and always shows a `.` (`3.0`); `bit` prints `yep`/`nop`.
- [Phase 5] Runtime: `Value` is a tagged struct (kind + 64-bit payload + one reference slot), so numbers never box; integers go through Int128 for exact checked math. Control flow (`yeet`, `bail`, `skip`) uses return codes, not exceptions. The program runs on a 256 MB thread with a call-depth limit of 10,000, after which `StackOverflow` (SE00301) is reported with an abbreviated trace. Every runtime error carries a SPLAT stack trace (function name + call-site span, most recent first) printed under the `Fix:` line; `rip "msg"` is `SE00305`.
- [Phase 5] Prelude for now: `squish(...)` (args joined by spaces, newline appended, stdout) and `yell(...)` (stderr). `slurp` and string helpers are Phase 6. Command-call `squish -x` is still a subtraction (Phase 3 rule); write `squish(-x)`. A prime "sieve" is trial division until arrays arrive in Milestone 3.
- [Phase 5] Constructs owned by later phases (tensors, indexing, member access, `me`, `&x`/`~x`, norms, `∂ ∫ ∑ ∏`, `guess/judge`, `@ .* \ >>`) type-check to a `HARD HAT AREA` (`NotYetBuilt`) error naming the owning phase. CLI: `splat run file` (exit 0 / 65 compile error / 66 missing file / 70 runtime error) and `splat check file`.
- [Phase 5] `spin c in some_txt` iterates the text one Unicode scalar at a time, with `c::char` (immutable, fresh per iteration). Compare with `c"a"`, not `"a"`. Indexing and `len` are still later phases.
