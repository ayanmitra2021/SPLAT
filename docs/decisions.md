# SPLAT design decisions

One line per decision, newest last. Format: `[Phase N] decision — reason`.

- [Phase 1] Target `net10.0` (SDK 10.0.404 installed); warnings are errors via `Directory.Build.props`.
- [Phase 1] `SourceSpan` lines/columns are 1-based; `Length` counts UTF-16 chars; end-of-file spans have length 0 and render with one caret.
- [Phase 1] A span running past its first line is underlined to the line end plus `...`; tabs in the source are copied into the caret padding so alignment holds at any tab width.
- [Phase 1] Spec section 9 messages are verbatim in `Templates`; the `Fix:` line is separate technical text. Quip rotation (new categories only) is seeded by line number so output is deterministic.
- [Phase 1] Color only when stderr is not redirected and `NO_COLOR` is unset.
- [Phase 2] `#- -#` block comments nest, so commented-out code may itself contain block comments. An unterminated one is reported at its opening `#-`.
- [Phase 2] Strings may span lines. Escapes: `\n \t \r \0 \" \ \{ \}`; an unknown escape is an error but is kept literally. A literal `{` must be written `\{`; a bare `}` is literal.
- [Phase 2] A string always lexes to one `String` token carrying `Parts` (`TextPart` / `ExprPart`). `ExprPart.Offset` is the file offset of the expression, so the parser re-lexes that range with `new Lexer(src, diag, offset, offset+len)` and gets correct spans. The format spec starts at the first top-level single `:` (not `::`/`:=`, not inside `()[]{}` or nested strings) and runs to the `}`.
- [Phase 2] `c"..."` is a `Char` token only when `c` is immediately followed by `"`; value is the Unicode scalar (int). Must contain exactly one scalar.
- [Phase 2] Integer literal value is `ulong` (range checking against i32/etc. and negation are the type checker's job); float value is `double`. Underscores are allowed anywhere inside digit runs. A number running straight into a letter/digit/underscore (`12abc`, `0b102`) is an error.
- [Phase 2] `:` inside `[...]` (innermost open bracket is `[`) is `SliceColon`; inside `(...)` within brackets it is a block `Colon` again. `::` and `:=` are always `DoubleColon` / `ColonAssign`.
- [Phase 2] `'` is `Transpose` only after Ident, `)`, `]`, `self`, or another transpose; `''` is one `ConjTranspose` token (so `A'''` = `''` then `'`). Elsewhere it is an error whose fix points at `c"a"`.
- [Phase 2] `||` is two adjacent `Pipe` tokens; the parser tells norm bars from lambda bars using `Token.SpaceBefore` (no space = adjacent). `|>` is `PipeGreater`, so write `||v|| > 3` with a space, not `||v||>3`.
- [Phase 2] `>>` is always `GreaterGreater`; the parser must split it when closing nested generics (`Maybe<Maybe<i32>>`).
- [Phase 2] Norm suffixes `_1`, `_inf`, `_F` lex as ordinary identifiers directly after the closing bars (`SpaceBefore == false`); the parser consumes them.
- [Phase 2] `grad/∂`, `intg/∫`, `sum/∑`, `prod/∏` share one `TokenKind` each. Because `sum`/`prod`/`grad`/`intg` are lexed as keywords, the parser (Phase 4/14) must accept them as plain function names when not followed by `[` (reduction/integral) or `(` (grad); until then they are reserved.
- [Phase 2] Extra assignment operators lexed beyond the spec list: `*=`, `/=`, `./=`. Bad characters and bad literals never stop lexing; `Lexer.Tokenize` never throws and always ends with `EndOfFile`.
- [Phase 2] `splat tokens file.splat` dumps tokens (stdout) and diagnostics (stderr, exit 65).
- [Spec v0.3] Added Milestone 5, the built-in data engine ("crates", spec §11, build plan Phases 19-28). It needs these later lexer changes (Phase 20): keyword `query`, duration literals (`5s`, `1mo`), date/stamp literals (`d"..."`, `t"..."`). The Phase 2 lexer is unchanged until then; today `5s` is reported as a bad number.
- [Phase 3] The parser is recursive descent for statements plus a Pratt loop for expressions. Binary table (spec 8.1): `**` (right-assoc, above unary) > unary `- ! & ~` > `@ .* ./ · \` > `* / % .+ .-` > `+ -` > `.. ..=` (non-associative; `1..2..3` is an error) > comparisons (left) > `and` > `or` > `|> >>` (left). `and` binds tighter than `or` (spec table lists them on one level; plan recommendation adopted). Assignment is a statement, not an expression.
- [Phase 3] Postfix `'`/`''`, calls, indexing (`A[:, 0..3]`, `:` alone is `FullSlice`), member access, `[a, b]` list literals and string-template interpolation already parse here. Lambdas, norms, calculus, reductions, `regress`/`classify` and data-engine forms are Phase 4+.
- [Phase 3] `:` opens a block and each `;` closes exactly one, so `;;` is simply two closers. An `if` chain (`if`/`elif`/`el`) is one statement closed by one `;`; a nested `if` takes the following `elif`/`el` (dangling-else), so it needs its own `;` first.
- [Phase 3] Whitespace stays insignificant, with three same-line rules: the value after `ret`/`rip` must start on the same line as the keyword; a command call's first argument must be on the same line as the callee; nothing else is newline-sensitive. So `x :=` followed by a statement on the next line is read as a continuation.
- [Phase 3] Command-call rule: only the prelude names `print`, `eprint`, `readl` may be called without parentheses, and only when the next token is on the same line, after a space, and is a literal, name, `self`/`super`, `!`, `&` or `~`. Arguments are comma-separated to the end of the expression. `f (x)` and `f(x)` are both ordinary calls; `-`, `[` and `(` never start a command argument.
- [Phase 3] Error recovery: missing `;` is reported once per unclosed block at its opening `:` (innermost first) when the file ends; a broken statement skips to the next statement keyword, `;`, `elif`/`el`, or an identifier starting a line; a missing `:` after an `if`/`elif`/`loop` header is reported and the body is parsed as if it were there; an orphan `elif`/`el` swallows its own header, body and `;`. A `;` sitting exactly where an error was just reported is not reported again at top level.
- [Phase 3] Nesting deeper than 200 (blocks, expressions, types) reports `TooDeep` instead of overflowing the stack.
- [Phase 3] `class trait extend enum pick try arena drop imp network train` are skipped by the parser with a `HARD HAT AREA` error (block skipping counts `:` and `;`, treating the `:` after `elif`/`el`/`catch` as a continuation) and appear in the AST as `ReservedStmt(keyword)`; the owning phase replaces that with real nodes. `regress`/`classify` are not statements, so they stay Phase 4.
- [Phase 3] `fn op <symbol>` parses `+ - * / % ** @ == != < <= > >=` and `[]` (Phase 8 rejects the unsupported ones); `fn op(...)` with a paren is a function named `op`. `init` and `deinit` are accepted as fn names. Generic bounds (`T: Trait`) and `$Dim` parameters parse; a closing `>>` or `>=` after generics is split by the parser.
- [Phase 3] `splat ast file` prints s-expressions, `splat ast --fmt file` prints canonical source. Tests assert `parse(format(parse(x)))` has the same s-expression and that the formatter is idempotent. `SPLAT_UPDATE_GOLDEN=1 dotnet test` rewrites the `.ast`/`.err` expectations in `tests/golden` for review.
- [Phase 4] Prefix `|` is a norm opener only when the next token is a `|` with no whitespace or newline before it (`||v||`); otherwise it opens a lambda. A zero-parameter lambda must be written `| | e`. Closing a norm uses the same adjacent-pair test, so `||a|| or ||b||` and `|x| ||x||` both parse. Lambda parameters are bare identifiers (no `::T` yet).
- [Phase 4] A lambda body is a full expression (extends as far right as possible, up to `,` `)` `]` `;`). `x |> |a| a + 1` therefore puts the whole `a + 1` in the lambda.
- [Phase 4] Norm suffixes accepted: `_1`, `_2` (same as no suffix), `_inf`, `_F`, and only when glued to the closing bars; any other `_name` glued there is an error. Postfix `'` after a norm is not valid (the lexer only emits Transpose after an identifier, `)`, `]` or `self`), and a norm is a scalar anyway.
- [Phase 4] `∑/sum[i in range] body` and `∏/prod[...]` take as body an expression parsed at the additive level, so the body absorbs `+ - * / % @ ...` but stops at `..`, comparisons, `and`/`or` and `|>`: `∑[i in 0..N] i + 1` is `∑(i + 1)`, while `∑[i in 0..N] i == 6` is `(∑ i) == 6`. Parenthesise to override. The formatter wraps a reduction in parentheses whenever it is an operand of arithmetic.
- [Phase 4] `∫/intg[r1, r2, ..., name = v] |x, y| body`: every non-named entry must be a `..`/`..=` range (anything else is a parse error), named entries are options (e.g. `tol`), and the integrand must be a lambda. `∂/grad` is a deriv node only when followed by `(`; `∫/intg`, `∑/sum`, `∏/prod` only when followed by `[`; otherwise all four are ordinary names (so `sum(v)`, `map(xs, sum)` work).
- [Phase 4] `regress(cfg) fit (X, y)` / `classify(cfg) fit (X, y)` parse to `FitExpr`. `cfg` is a normal argument list: bare names (`linear`), calls (`svm(kernel = "rbf")`) and `name = value` entries. The result is a primary expression, so `model(&X)` and `.r2(...)` chain off it. Mapping of keywords to algorithms is Phase 15's job.
- [Phase 4] `splat ast -e "<expr>"` prints one expression as a single-line s-expression (used for the precedence table). Float literals print as .NET round-trip text (`1E-06`).
- [Cross-phase] Diagnostic IDs: every diagnostic has a permanent ID, `SE` + 5 digits (error) or `SW` + 5 digits (warning), separate sequences, never renumbered or reused. Registry: `DiagnosticCodes.Table` in `Splat.Core` (one entry per `DiagnosticCategory`), exposed as `Diagnostic.Code`. `ConsolePrinter` prints `[SE00001] ` before the headline; `Message` text (spec 9 wording) is unchanged. Blocks: 00001 lex/parse, 00100 names/types/shapes, 00200 ownership/zones, 00300 runtime, 00400 OOP/patterns, 01000 data engine (reserved in spec 9), 90000 internal. `DiagnosticCodeTests` fails on an unregistered category, a duplicate code, or a severity/prefix mismatch. Introduced after Phase 4; existing categories were assigned codes then and golden `.err` files regenerated.
- [Phase 5] Pipeline: lex -> parse -> `TypeChecker` (one static pass over the whole program) -> `Interpreter`. Nothing runs if the checker reports an error, so type errors always precede side effects. The checker records literal types, fn signatures, pipe desugarings and named-argument maps in `TypeInfo`, which the interpreter reads (the interpreter never re-infers).
- [Phase 5] Types: `i8 i16 i32 i64 u8 u16 u32 u64 usize f16 f32 f64 bool txt char unit`, `range<T>` and `fn(A)::R`. The char type is named `char` (the spec lists no name). `f16` is IEEE half, `f32` f32, `f64` f64, and every float result is rounded to its own precision. `usize` is 64-bit unsigned.
- [Phase 5] Literal defaulting: an integer literal is `i32`, a float literal is `f32`, but a literal takes the type its context asks for (annotation, parameter type, the other operand: `n + 1` with `n::i64` is an i64 add). An integer literal never becomes a float and vice versa (`x::f32 = 42` is an error; write `42.0`). A literal that does not fit is a compile error (`-128` fits an i8).
- [Phase 5] No implicit conversions at all. Explicit conversion syntax is the type name as a function: `f32(x)`, `i64(n)`, `u32(c"A")`, `char(97)`, `txt(v)` (any value, including ranges). `T(x)` is checked at runtime for range (`BadConversion`); float to int truncates toward zero; NaN/inf are errors. `bool(x)` does not exist (compare instead). A user binding named like a type shadows the conversion.
- [Phase 5] Integer arithmetic is CHECKED, never wrapping: any result outside the type's range is `IntegerOverflow` (SE00304). Division/remainder truncate toward zero and divide-by-zero is an error; float division by zero is IEEE (inf/NaN). `**` on integers with a negative exponent is a runtime `MathDomain` error (SE00307). `+` also concatenates two `txt`. Comparisons need identical types; `txt` compares by ordinal UTF-16 code units.
- [Phase 5] Scoping: `:=` is immutable, `var` mutable, only `var` can be reassigned (`=`, `+= -= *= /=`; the reassigned value must keep the variable's type). Shadowing in a nested scope is allowed (and may change the type); redeclaring a name in the SAME scope is an error (`Redeclared`, SE00107), because closures capture by reference and a same-scope rebind would change their view. Phase 6's REPL will relax this for session-level names. A bind's initialiser sees the outer binding (`x := x + 1` in a nested block). Variables must be declared before use; functions are hoisted per block so mutual recursion works. A `loop i in` variable is immutable and fresh per iteration.
- [Phase 5] Functions: parameters must be annotated; the return type defaults to `unit` for block bodies and is inferred for `= expr` bodies (a self-recursive one needs `::T`, `CannotInfer` SE00112). The value of a block body is `ret`'s value or its LAST expression (also through an `if ... el` chain); a function with a non-`unit` return type must return on every path (`MissingReturn`, SE00110); a trailing `loop:` with no `br` counts as returning. Defaults (`h::i32 = 2`) and named arguments work for `fn` declarations, not for function-typed values. Generic parameters (`<T>`) are accepted and treated as "any" until Phase 7.
- [Phase 5] Lambda parameters are inferred from context (an expected `fn(...)::R` type, or the left side of `|>`); with no context they must be annotated `|x::i64| ...` (parser change: `LambdaParam` gained an optional `Type`). Closures capture variables by reference (shared mutable cell), so a closure counter works.
- [Phase 5] `x |> f` is `f(x)` and `x |> f(a, b)` is `f(x, a, b)` (left side becomes the first argument); the checker stores the desugared call and the interpreter runs it.
- [Phase 5] Format specs in `{x:spec}`: `[<>^]? 0? width? .precision? [xXbo]?`. Precision is for floats only, radix letters for integers only, validated at check time (`BadFormat`, SE00111). Numbers default to right alignment, text to left; negative numbers in a radix print as `-` plus magnitude. A float prints in shortest round-trip form and always shows a `.` (`3.0`); `bool` prints `true`/`false`.
- [Phase 5] Runtime: `Value` is a tagged struct (kind + 64-bit payload + one reference slot), so numbers never box; integers go through Int128 for exact checked math. Control flow (`ret`, `br`, `cont`) uses return codes, not exceptions. The program runs on a 256 MB thread with a call-depth limit of 10,000, after which `StackOverflow` (SE00301) is reported with an abbreviated trace. Every runtime error carries a SPLAT stack trace (function name + call-site span, most recent first) printed under the `Fix:` line; `rip "msg"` is `SE00305`.
- [Phase 5] Prelude for now: `print(...)` (args joined by spaces, newline appended, stdout) and `eprint(...)` (stderr). `readl` and string helpers are Phase 6. Command-call `print -x` is still a subtraction (Phase 3 rule); write `print(-x)`. A prime "sieve" is trial division until arrays arrive in Milestone 3.
- [Phase 5] Constructs owned by later phases (tensors, indexing, member access, `self`, `&x`/`~x`, norms, `∂ ∫ ∑ ∏`, `regress/classify`, `@ .* \ >>`) type-check to a `HARD HAT AREA` (`NotYetBuilt`) error naming the owning phase. CLI: `splat run file` (exit 0 / 65 compile error / 66 missing file / 70 runtime error) and `splat check file`.
- [Phase 5] `loop c in some_txt` iterates the text one Unicode scalar at a time, with `c::char` (immutable, fresh per iteration). Compare with `c"a"`, not `"a"`. Indexing and `len` are still later phases.
- [Phase 6] `by` and `then` are contextual: ordinary identifiers everywhere, operators only when they follow an expression on the SAME line (a `by`/`then` at the start of a line is always a name). Precedence, tightest first: `..`/`..=` (50) > `by` (48) > `then` (45) > `in` and comparisons (40). So `x in 0..10 by 2 then 50..100` is `x in ((0..10 by 2) then (50..100))`. `by` accepts only a bare range on its left (`rev(..)` and `then` chains cannot be stepped; `a..b by 2 by 3` is an error); its operand parses above range level (`by n + 1` steps by `n + 1`). `then` chains flatten into one `ChainExpr`; the checker types it `chain<T>` and every part must be iterable with the same element type (`BROKEN CHAIN`, SE00114). Later parts of a chain take the first part's element type as a hint, so `0..n then 50..100` agree.
- [Phase 6] `x in S` is a level-9 operator parsed in the Pratt loop (`TokenKind.In` joined the binary table). The right side may be a range (membership respects `by`, bounds and `..=`), a `txt` (`char in txt` tests a character, `txt in txt` a substring, empty substring is always found), a chain (any part), or the parenthesised list `(a, b, c)`, which the parser accepts only directly after `in` (`ParenListExpr`; a trailing comma is allowed, a single `(x)` is plain grouping). The list desugars to `==` tests, short-circuiting, and needs every member to have exactly the left operand's primitive type. The left operand must match the element type exactly (a bare literal adopts it, so `x::i64 in 0..3` works). No `not in`; write `!(x in S)`.
- [Phase 6] Steps: zero or negative steps are `BadStep` (SE00113), at check time for literal steps and at run time otherwise (same ID). `rev(range)` yields the same values from the last back down to the first (also for stepped ranges); `rev` of anything but a range is a type error until lists arrive. Ranges are lazy (a range over the whole u64 space costs nothing until walked) and counted in 128-bit arithmetic, so no step can overflow.
- [Phase 6] One internal "iterable" notion replaces the per-type branches: `TypeChecker.ElementOf` (static) and `Interpreter.Iterate`/`Contains` (runtime). Lists, sets, maps, tensors and `trait Iterable` (Phases 7, 9, 12) plug in at those two places. The non-iterable `TypeMismatch` now says "something iterable (a range, a txt, ...)".
- [Phase 6] Prelude (shared signature table in `Splat.Semantics.Prelude`): `print`/`eprint` (variadic), `readl()` / `readl(prompt)` (prompt goes to stdout with no newline; returns one line without its line ending; at end of input returns `""` until `Maybe` can say "no line"), `len(txt)::usize` (counts Unicode scalars, matching `loop`), `upper`, `lower`, `trim`, `parse_i32/parse_i64/parse_mid/parse_chonk(txt)` (surrounding whitespace allowed; non-finite floats rejected). `len` returns `usize` (spec: `enumerate` yields `usize`), so mixing it with `i32` needs `i32(len(s))`. Parse failure is a `rip` (SE00305) marked TODO(Phase 7): they become `Maybe<T>` then. User bindings shadow all prelude names. Prelude functions are still not first-class values (`f := upper` is HARD HAT, now pointing at Phase 7).
- [Phase 6] `SessionState`: each REPL entry is lexed, parsed, checked and run against a persistent session. An entry gets a fresh `Scope`/`Env` chained onto the last committed entry and becomes the new tip only on success, so a failed entry (parse error, type error or runtime error) adds no bindings, and `var` variables it already assigned are restored from a snapshot. Output already written is not unwritten, and state captured inside a closure's own scope is not rolled back. The `TypeInfo` is shared by all entries so functions from earlier entries keep their types. Redeclaring a top-level name in a later entry is allowed (shadowing; earlier functions keep the definition they were checked against, because they only see the chain as it was); redeclaring within one entry is still `Redeclared`.
- [Phase 6] REPL: prompt `splat> `, continuation `  ...> ` (prompts and banner only on a real terminal, so piped input gives clean output). Continuation is decided from tokens: an unterminated string or `#-`, an unclosed `(`/`[`, or more `:` block openers than `;` closers (the `:` after `elif`/`el`/`catch` continues an open block). A stray extra `;`/`)` is not "incomplete"; the parser reports it. End of input inside an open block still submits the entry so the missing `;` is reported. An expression statement whose type is not `unit` echoes `=> value :: type` (text and chars show their quotes); only the last statement of an entry echoes. Commands (only at the start of an entry): `:help :reset :load <file> :vars :history :quit` (`:q`, `:exit`); an unknown command is `UnknownCommand` (SE00012). `:load` runs the file as ONE transactional entry (all or nothing, no echo, spans name the file). `readl` in the REPL reads from the same input as the REPL, so a piped transcript can answer it. History is `:history` plus whatever line editing the host terminal gives `Console.ReadLine`.
- [Phase 6] CLI: `splat` or `splat repl` starts the REPL; `run`, `check`, `tokens`, `ast` unchanged; `run` feeds `readl` from stdin. Exit codes: 0 ok, 64 usage, 65 compile error, 66 file not found, 70 runtime error. Diagnostics audit: every error path in Phases 2-5 already goes through `Templates` (the parser's only raw throws are `ParseAbort` after a report; the interpreter's catch-all reports `Internal`); nothing else needed adding.
- [Phase 6] The `tests/golden/control_flow.ast` expectation had gone stale (the program's loop bound is 20, the expectation said 10); regenerated by hand.
- [Phase 7] Enums: `enum Name<T, E>: A(T), B ;`. An enum declaration is hoisted like a `fn`: every enum in a block is registered (names first, then payloads) before anything else is checked, so functions may use an enum declared later and enums may be recursive or mutually recursive. Variant names are unqualified and must be unique inside one program/REPL entry (`Redeclared` SE00107 otherwise); a later REPL entry or a user enum may shadow an earlier or built-in one. Only `Maybe<T>` (`Got(T)` / `Nada`) is built in. A `Result` type is not built in: the spec's `Result<T, E>` (4.4) is a user enum, and a built-in one would only collide with it.
- [Phase 7] Registries chain (`EnumRegistry`): built-in root, one child per program or REPL entry, committed only when the entry succeeds. Variants live outside the symbol table and the runtime environment, so `Nada` never shows up as a user binding. A user binding with a variant's name shadows the variant. A payload variant is not a first-class function value (it must be called).
- [Phase 7] Generics: every call of a generic function (or constructor) gives each type parameter a fresh inference variable and unifies argument types with parameter types; that is the checked instantiation, recorded for later phases in `TypeInfo.TypeArgs`. The expected type only guides how literals are typed (`x::Maybe<i64> = Got(5)` makes the 5 an i64) and never binds the variables, so a wrong guess is one mismatch on the result. Lambda arguments are checked after the others. An unconstrained `T` supports nothing but being stored, passed, returned, compared structurally and put in collections; `T: Trait` bounds are parsed and enforced from Phase 9. The interpreter stays dynamically typed, so there is no separate monomorphization pass yet.
- [Phase 7] `pick` arms are `Pattern => expr` separated by commas, or a block `Pattern: stmts ;`. A command call (`print "x {v}"`) is allowed as an `=>` body with exactly one argument (the comma ends the arm). All arms must have one type (an arm of another type is an IDENTITY CRISIS); a `pick` with block arms has type `unit`. A capitalised pattern name is a variant, anything else binds; there are no or-patterns or guards. A `pick` is an expression, so it can be used as a statement, a value, or a function body.
- [Phase 7] Exhaustiveness and redundancy use the Maranget usefulness/matrix algorithm (`PatternMatrix`). Integer and char columns are cut into segments at every range boundary, so `0`, `1..=9`, `_` is handled exactly and a missing range is reported as an interval; text and floats have no finite signature, so they always need a catch-all. The error lists up to four missing witnesses (`Got(Nada)`, `(false, true)`, `-128..=-1`). Redundancy is warning SW00400 (the program still runs). Both checks are skipped when the patterns were already reported as ill-typed, to avoid noise.
- [Phase 7] `parse_i32/i64/f32/f64` now return `Maybe<T>` (`Nada` for text that is not a number of that type, including out-of-range and non-finite values); they no longer `rip`. `readl` stays a plain `txt` (`""` at end of input), as the spec examples use it.
- [Phase 7] Collections: `List<T>` (`[a, b]`), `Set<T>` (`set(a, b)`), `Map<K, V>` (`map(k => v, ...)`; `k => v` is a pair that is only legal as a `map` argument), tuples `(a, b)` (two or more elements; `(x)` groups, `()` is unit; tuple types `(A, B)`; destructuring bind `(a, b) := f()`). Sets and maps keep insertion order. Hashable: integers, char, txt, bool and tuples of those; floats, unit, lists, sets, maps and enums are not (`NotHashable` SE00406, at compile time where the type is known). `set()`, `map()` and `[]` need a type annotation (CannotInfer SE00112).
- [Phase 7] Methods of the built-in collections are checked specially until `extend` (Phase 9) makes them ordinary: List `push pop insert remove`, Set `add remove`, Map `remove get`. `pop`, `Map.remove` and `Map.get` return `Maybe`. Mutating methods and `xs[i] = v` / `m[k] = v` (also `+=` and friends) need the root of the receiver to be a `var` variable (`ImmutableMutation` SE00404); parameters are immutable. `~` bindings arrive with ownership in Phase 17. Out-of-range indices (negatives included), slices, `insert`/`remove` positions and missing map keys are runtime errors with spans (SE00403, SE00308). `xs[a..b]` copies, supports `by` and `rev`, and is not a view. `+` concatenates two lists of one type. `==`/`!=` compare any two values of one type structurally.
- [Phase 7] Until ownership (Phase 17), collections have value semantics at the points where aliasing would show: binding, assignment, storing into another collection, and pushing copy the collection (deeply) unless the expression just built a fresh one, so `var b = a; b.push(1)` never changes `a`. Function arguments are not copied (parameters cannot be mutated). `loop` walks a snapshot of the collection taken when the loop starts.
- [Phase 7] Mutation while iterating: inside `loop x in S`, assigning to the subject variable (or an element of it), calling a mutating method on it, or poking it (`~S`) is `MutateWhileIterating` SE00405, for a plain name, the parts of a `then` chain, and the arguments of `rev`/`enumerate`/`zip`. The scan covers nested `if`/`loop`/`pick` blocks, stops where the body redeclares the name, and cannot see through a function call (the snapshot rule keeps that case safe at run time). `loop (k, v) in m` and `loop k, v in m` are the same; each desugars to a hidden loop variable plus `(k, v) := hidden`.
- [Phase 7] A `(` or `[` that starts a new line begins a new statement instead of calling or indexing the value before it, so `(a, b) := f()` and `[1, 2]` can start a line. `zip(a, b)`, `set`, `map`, `len` and the other prelude names take priority over a conversion of the same name (the unit type used to be named `zip`; it is `unit` now, so the clash is gone). A command call still never takes `(` or `[` as its first argument, so `print [1, 2] == xs` needs parentheses: `print([1, 2] == xs)`.
- [Phase 7] The Phase 6 hard-hat messages for "prelude name used as a value" now point at Phase 10 (they were wrongly labelled Phase 7). Warnings are printed to stderr by `splat run`/`check` even when the program succeeds.
- [Vocabulary v0.5] Keywords were renamed to familiar, short words; the `:` / `;` block syntax and the comedic diagnostics are unchanged. - [Vocabulary v0.5] Types: `bit`→`bool`, `zip`→`unit` (the `zip(a, b)` prelude function keeps its name, which also ends the old clash between the type and the function), `smol/mid/chonk`→`f16/f32/f64`, `usz`→`usize`. Inside a `query` block a clause-initial `drop` is the row filter; elsewhere `drop x` is the early-drop statement, so position disambiguates.
